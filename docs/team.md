# 팀 편성 (팀장 / 책임 / 신입)

| 직급 | 모델 | 역할 |
|---|---|---|
| 팀장 (메인 Claude) | sonnet 5.5 | 요구사항 정리, 배분, 최종 검수·보고. 소규모 수정은 직접 |
| 책임 (senior) | opus | 설계, 난제 구현, 큰 변경 리뷰만 |
| 신입 (junior) | sonnet | 일반 구현·UI·버그 수정·문서화 주력 |

## 배분
1. 기본 구현은 신입. 책임은 설계/막힌 곳/리뷰에만.
2. 흐름: 책임 설계(필요 시) → 신입 구현 → 책임 리뷰(큰 변경만) → 팀장 확인.
3. 같은 파일 동시 수정 금지.

## 위임 판별 기준
**무조건 책임(senior)**
- 제작 파이프라인 상태 전이·영수증·복구 로직 (production-jobs, production-local-recovery 계열)
- 렌더링 핵심, 인증·세션, 결제, 클라우드 릴레이 허용 경로(보안 경계)
- 원인이 여러 계층에 걸친 막힘(서버+확장+클라우드)

**팀장 직접**
- 파일 1~3개 범위의 화면·문구·설정 수정, 단순 서버 라우트 추가, 배포·재기동·검증

**신입(junior)**
- 설계가 정해진 UI/폼/API 구현, 문서화, 파일 정리

**애매하면**: 책임에게 먼저 영향 범위만 묻는다(구현 금지). 한 번 위임한 일은 팀장이 같은 파일을 동시에 건드리지 않는다.

## 위임 브리프 필수 항목
현재 상태 / 이미 확인·배제한 것 / 대상 파일 / 금지 사항(재시작·배포·git·실제 작업 변경) / 완료 기준.

## 결과 검수 (팀장)
보고를 그대로 믿지 않는다: 테스트 재실행 + 실제 동작 확인 후에만 재기동·배포. 서버 재기동·배포·실제 작업 상태 변경은 팀장만.
